Build a “Client Database” feature for our web app (Clinical Note Generator) for a SINGLE CLINIC (single-tenant). This database must support:
1) manually adding/editing/archiving clients,
2) importing clients from CSV (and exporting to CSV),
3) search/filter/sort + client detail pages,
4) tight integration with our Quo (phone/SMS) and Gmail areas so new phone numbers/emails can be matched to existing clients and/or added when it makes sense,
5) an “Unmatched Contacts Inbox” workflow for linking/creating clients from Quo/Gmail identities.

Primary goal: make the Client Database the source of truth for identity matching (phone/email), while still supporting MRN as a column.

--------------------------------------------
B) DATA MODEL (Prisma)
--------------------------------------------

Client (single clinic)
- id: String @id @default(uuid())
- firstName: String (required)
- lastName: String (required)
- preferredName: String? (optional)
- dob: DateTime? (optional)
- mrn: String? (optional, UNIQUE if present)   <-- ADD THIS COLUMN
- emailPrimary: String? (optional)             <-- optional convenience field (still store real emails in ClientContact)
- phonePrimary: String? (optional)             <-- optional convenience field (still store real phones in ClientContact)
- status: enum("active","inactive","archived") default "active"
- createdAt, updatedAt, lastVisitAt?
- notesInternal: String? (text)

ClientContact (new)
A client can have multiple phones/emails.
- id: String @id @default(uuid())
- clientId: String (FK Client)
- type: enum("phone","email")
- value: String                     // normalized: E.164 for phone, lowercase for email
- label: String?                    // Mobile, Home, Work
- isPrimary: Boolean @default(false)
- isVerified: Boolean @default(false)
- source: enum("manual","quo","gmail","import")
- createdAt, updatedAt

Constraints / Indexes:
- @@unique([type, value])           // global uniqueness across clients (single clinic)
- @@index([clientId])

InboundIdentityEvent (new)
Tracks identities observed in Quo/Gmail that may or may not match existing clients.
- id: String @id @default(uuid())
- source: enum("quo","gmail")
- kind: enum("phone","email")
- value: String?                    // normalized (nullable if normalization fails)
- displayValue: String?             // original raw text (e.g., "(212) 555-..." or "John <x@y.com>")
- occurredAt: DateTime
- status: enum("new","linked","ignored") @default("new")
- linkedClientId: String? (FK Client nullable)
- meta: Json?                       // minimal metadata ONLY (threadId/messageId/direction), no message bodies
- createdAt, updatedAt

Indexes:
- @@index([source, kind, status])
- @@index([value])

ClientImportJob (new or keep)
- id: String @id @default(uuid())
- filename: String
- createdAt: DateTime @default(now())
- totalRows: Int
- importedCount: Int
- updatedCount: Int
- skippedCount: Int
- errorCount: Int
- errorReport: Json?                // row-level errors; do not log PHI server-side

--------------------------------------------
C) NORMALIZATION + MATCHING
--------------------------------------------

Phone normalization:
- Use libphonenumber-js to parse/format to E.164.
- Store normalized E.164 in ClientContact.value.
- If normalization fails, create InboundIdentityEvent with value=null and displayValue set; UI should prompt to correct.

Email normalization:
- Lowercase + trim. Basic validation.

Matching priority for Quo/Gmail:
1) Match ClientContact(type,value)
2) If not matched:
   - Create InboundIdentityEvent(status="new") and show in Inbox
DO NOT auto-create clients silently.

When linking inbound identity to existing client:
- Create ClientContact(source=quo/gmail, isPrimary optional).
- If client has no primary of that type, suggest making it primary.
- Mark event linkedClientId + status="linked".

When creating a new client from inbound identity:
- Create Client with minimal required fields (firstName/lastName must be provided; allow placeholder “Unknown” only if user explicitly chooses).
- Create ClientContact for inbound identity.
- Mark event linked.

Dedup rules in manual add/import:
- MRN: if present and exists -> treat as match candidate:
  - If “Update matches” enabled: update existing
  - Else: skip with a warning
- If MRN missing:
  - name + DOB match should be a “possible duplicate” warning only; do not auto-merge.

--------------------------------------------
D) API ENDPOINTS (Express)
--------------------------------------------

Clients
- GET  /api/clients?search=&status=&sort=&page=&pageSize=
  search matches: lastName, firstName, preferredName, mrn, primary phone, primary email
- POST /api/clients
- GET  /api/clients/:id
- PUT  /api/clients/:id
- PATCH /api/clients/:id/status   body: { status }
- GET  /api/clients/:id/contacts
- POST /api/clients/:id/contacts  body: { type, value, label?, isPrimary? }
- PATCH /api/contacts/:contactId  body: { label?, isPrimary?, isVerified? }
- DELETE /api/contacts/:contactId

Import / Export
- POST /api/clients/import
  supports CSV upload
  supports header mapping payload
  returns job summary and downloadable error report id
- GET /api/clients/import/:jobId
- GET /api/clients/export   returns CSV

Inbound Identity Inbox
- GET  /api/inbox/identities?source=&status=
- POST /api/inbox/identities/link
  body: { eventId, clientId, makePrimary?: boolean, label?: string }
- POST /api/inbox/identities/create-client
  body: { eventId, client: { firstName, lastName, preferredName?, dob?, mrn? }, makePrimary?: boolean, label?: string }
- POST /api/inbox/identities/ignore
  body: { eventId, reason?: string }

Integration hooks (called by Quo/Gmail areas)
- POST /api/integrations/quo/inbound
  body: { phone: string, occurredAt?: string, meta?: { messageId?, direction?, threadId? } }
- POST /api/integrations/gmail/inbound
  body: { email: string, occurredAt?: string, meta?: { messageId?, threadId?, subjectHash? } }

Inbound endpoints must:
- normalize phone/email
- attempt match against ClientContact
- if matched: return { matched: true, clientId }
- if not matched: create InboundIdentityEvent and return { matched: false, eventId }
